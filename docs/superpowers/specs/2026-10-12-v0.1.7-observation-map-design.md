# Signal Atlas v0.1.7: observation map replacement

Date: 12 October 2026

Status: approved by the user on 12 October 2026. Product implementation awaits implementation-plan review and execution-method selection.

Baseline: `feature/revised-inputs`, commit `9fa26df3cd79d709c0d5eb2db074d220a65b5ea2`, v0.1.6-preview.2.5. Work branch: `codex/v0.1.7-map`.

## Objective and scope

Replace the paginated Patterns/Emitters directory and the separate Cycle explorer navigation with one continuous, zoomable observation atlas. The primary object on the map is an observation window, with one stable tile per window. Switching arrangements moves those same tiles; it does not substitute emitter summary cards for observations.

Retain synchronized event intake, originals, source windows, emitter/candidate profiles, reviewed patterns, variants, scoped evidence, reviewed relationships, unresolved observations, revision history, IndexedDB storage and complete backup/restore. Reorganizing the atlas must not change emitter attribution or delete historical browser data.

The map draws on the completed Three Body Orbits study summarized in the chat “Analyze Three Body Orbits map”: pointer-anchored zoom, progressive detail, smooth movement between arrangements, filtering by dimming in place, and smooth camera travel. Its unrecovered embedding recipe is not a requirement to reproduce an exact island arrangement.

The release identifier is **0.1.7**. This specification authorizes preparing that version after the required design and plan reviews; it does not report the release as implemented or deployed.

## Agreed product requirements

### One map, two arrangements

- **Similarity:** group observation windows using Frequency, PRI, pulse width, or any nonempty combination of those three parameters. Show the active combination explicitly.
- **Emitter:** group the same observation windows by their emitter/candidate profile. Uncertain candidates get their own labelled islands; similarity does not assign emitter identity.
- Changing the parameter combination recomputes similarity groups and animates tiles to their new locations. It also updates suggestions, highlights and percentages using the same comparison parameters.
- In emitter arrangement, parameter changes update matching and evidence eligibility while retaining emitter island and tile positions.
- Browse the complete retained window collection on one map. Viewport rendering may omit offscreen graphics; there is no 24-card pagination limit on the map's collection.

### Similarity groups and evidence

- Every pair within a similarity group must meet the chosen threshold using the complete selected windows. Use deterministic complete-link clustering; arrival order and emitter identity do not define similarity groups.
- Full-window group scores must be symmetric. Compute both directed whole-window comparisons and use their minimum so one direction cannot hide unsupported evidence.
- Every selected parameter must have sufficient supplied, compatible measured evidence in both windows. A missing selected parameter cannot be silently removed from the score.
- Single-parameter grouping requires the configured minimum of distinct aligned measurements in that parameter. Multi-parameter grouping additionally requires the minimum number of distinct aligned positions simultaneously supported across all selected parameters. The initial minimum is 16 and remains provisional.
- Preserve one shared monotonic time/event alignment across the selected channels. Global offset and duration scaling remain allowed; independent channel shifts, reversal and local time warping do not.
- Shape and relative timing remain primary. Absolute-level and duration penalties retain the current adjustable controls. Initially use the existing 85% threshold with explicit provisional labelling; do not import the historical cycle atlas's 65% threshold or formula/vision blend.
- Steady observations remain admissible. Their lack of shape information must appear in comparison explanations; absolute values remain inspectable.
- In similarity arrangement, observations failing selected-parameter evidence requirements appear in a labelled **Insufficient evidence** area. Explain which selected channels or overlap requirements are missing.
- In emitter arrangement, these observations remain within their emitter islands and are dimmed. Their recordings and review history stay available.
- Group boundaries describe complete-link similarity under the current parameters and settings, not emitter identity or physical classes. Reviewed pattern and relationship IDs remain stable when these exploratory boundaries change.

### Whole-window and partial matches

- Selecting a tile considers every other observation window, including unreviewed windows. Exclude self-comparison by window ID; preserve shared capture/source lineage in explanations.
- Calculate and retain the whole-window result separately from the best contiguous partial result. A stronger partial score must not overwrite an available qualifying whole-window match.
- Qualifying whole-window matches rank before qualifying partial matches, then by score and stable ID. A partial match may connect observations in different groups.
- Highlight every qualifying destination, regardless of the number of drawn connections. The initial connection limit is eight, with an accurate count such as **8 of 37 matches** and a control to expand it.
- The map's primary highlighted/ranked set requires evidence for every selected parameter. Partial-channel candidates remain available as explicitly scoped evidence in the inspector; their subset score is not presented as a full selected-parameter percentage and does not admit them into a group.
- Record exact query/target window IDs, supported channel IDs, matched source intervals, settings/matcher versions, and whether the result is whole-window, temporal partial, or partial-channel.
- The existing bounded feature and interval search remains approximate for long windows. Explanations disclose approximation and preserve access to raw events.

### Review when a destination is unreviewed

Map exploration never creates a reviewed pattern, emitter attribution or accepted support automatically.

Selecting a destination without a reviewed pattern permits comparison and explanation. Before accepting it as a pattern target, the analyst explicitly creates a reviewed pattern for that destination with a name/explanation. This action uses the existing pattern creation workflow, after which support/variant/challenge review can proceed. Do not invent a target pattern silently.

For already reviewed destinations, resolve the pattern represented or supported by that exact destination window. If it supports several patterns, require an explicit target-pattern choice in the review UI. Preserve the actual compared target window and interval; do not substitute a different representative's diagnostics. Extend stale-context validation to check that the selected target window remains evidence for the chosen pattern and revision.

Cross-emitter acceptance retains separate emitter-specific patterns and records a reviewed relationship. Selecting a supporting observation can expose the existing pattern it supports without duplicating its tile.

### Connection overlay, colours and legend

- Render tile backgrounds, traces and badges below a dedicated connection overlay. Lines and percentage labels must stay above every tile, including a selected or highlighted tile.
- Use solid connections for reviewed relationships, dashed connections for whole-window suggestions, and a distinct dash-dot style plus **Partial** text for temporal partial suggestions.
- Reviewed connections expose saved evidence. Display a historical score only if labelled with its recorded parameter/settings scope; do not imply it was recomputed under the current mask.
- Connection endpoints attach to tile boundaries. Percentage labels use readable screen-space sizing and a contrasting backing. Decorative line spans do not block tile interaction; deliberate line/label hit targets open the corresponding comparison.
- Selection reveals relevant reviewed connections and ranked suggestions. **Show links** also reveals other reviewed connections whose endpoints are visible. Suggested edges remain anchored to the selected observation rather than drawing every possible pair in the collection.
- A colour-and-text badge distinguishes **Unreviewed**, **Reviewed/associated**, and **Unresolved** windows. Additional support, variant and challenge roles appear as text/icon badges. Region colour conveys group identity separately from review status.
- A persistent, keyboard-accessible legend explains review status colours, selected/highlighted/dimmed states, complete-link group boundaries, reviewed/full/partial connection styles, active comparison parameters and percentages as resemblance rather than probabilities.
- A textual connection list provides an accessible alternative and navigation to offscreen destinations. A selected edge exposes its measured channels, interval and limitations in the inspector.

### Spatial arrangement and camera

- Place broadly similar groups near one another using distances derived from the symmetric whole-window scores between eligible group representatives. Deterministic projection supplies approximate group centres; packing adjusts centres for separate readable islands and label space.
- Do not derive screen distance from emitter labels. Do not claim that physical screen distances equal the displayed resemblance percentages.
- Pairs incompatible under active unit/evidence requirements are not assigned an invented numerical distance. Separate compatible components are packed deterministically with explicit incompatibility information.
- Emitter islands use stable profile identities and retain their placement when only comparison parameters or display filters change. Tile slots are derived independently of those controls.
- Pan by pointer drag; support wheel zoom, pinch zoom, keyboard pan, zoom buttons, reset/fit collection, focus selected observation and **Focus matches**. Zoom stays anchored to the pointer/pinch centre.
- Animate group/arrangement changes and camera focus. Use about 950 ms as the initial arrangement duration from the reference study, subject to responsiveness checks. Interrupted transitions begin from currently displayed coordinates, not from old endpoints.
- Keep selection while rearranging. Render links from the current animated endpoint coordinates so they remain attached during movement.
- Respect reduced motion by applying destination coordinates and camera positions without transition animation. Dragging must not accidentally select a tile.

### Progressive zoom and display filters

- Overview: compact status-coloured markers with group names and counts.
- Middle zoom: miniature observed traces for the active selected parameters.
- Close zoom: larger aligned traces, observation name, review badge and selected match detail. The evidence inspector remains the full-detail view.
- Select detail levels using actual projected tile size, with crossfades around thresholds. Do not create repetition or fill missing values for decorative playback.
- Display filters for search, emitter/candidate and review status dim nonmatches in place by default. An optional **Hide nonmatches** control hides their graphics without repacking islands or changing analytical membership.
- **Focus matches** moves the camera to the matching bounds. Clearing filters restores the same coordinates. Distinguish these display filters from the parameter controls that change the comparison itself.
- Offscreen rendering is an optimization only; match totals, clustering, group counts, selection navigation and backups cover the full collection.

## Architecture and approach

### Chosen approach: layered SVG map with worker-based analysis

Use an SVG world-coordinate scene with HTML controls and the existing HTML evidence inspector. This builds on the older atlas's camera/pointer mechanics while supporting the new observation model. Render layers in a deliberate order: group areas, observation markers/previews, focus/highlight treatment, connection paths, and readable edge labels/hit targets.

Separate the following responsibilities into focused modules:

1. **Comparison selection and evidence eligibility:** canonical nonempty parameter mask, supported channels, overlap rules, compatibility, and settings fingerprint.
2. **Observation matching:** whole/partial results for all windows, full-first ranking, complete diagnostics and existing reviewed-pattern associations.
3. **Grouping worker:** symmetric cached pair scores, complete-link partition, group representatives and cancellation/progress.
4. **Map layout:** similarity projection, collision-free island packing, stable emitter placement, insufficient-evidence placement, and stable window coordinates.
5. **Camera and transition controller:** world/screen conversion, pointer gestures, focus bounds, current-position interruption and reduced motion.
6. **Map renderer and legend:** semantic zoom, viewport culling, status/filter/highlight treatment and the topmost connection layer.
7. **Application integration:** existing intake/review/storage/restore flow, map toolbar and selection-driven inspector.

Alternatives considered:

- Retaining the current grid and adding CSS scaling would preserve pagination and document-flow layout, which fails the agreed continuous-map interaction.
- A Canvas/WebGL replacement could support much larger collections but introduces more custom text, hit-testing and accessibility work. SVG with viewport culling is the first implementation for the agreed 500-window pilot; profiling determines whether further rendering changes are warranted.

### Data and worker flow

The durable domain entities remain intact. A selected parameter mask joins the comparison settings with a backwards-compatible default of Frequency + PRI + PW when absent. Preserve old recorded diagnostics/settings strings as historical evidence, rather than rewriting decisions.

Store ephemeral browsing state separately: camera, arrangement, selection, filters, hidden/dimmed preference and connection limit. It must not influence grouping or be mistaken for durable review decisions.

Workers operate on bounded observed window features, not duplicated 100,000-event recordings. Cache whole-window pair comparisons by both window fingerprints, bounds, selected mask, matcher version and numeric settings. Use separate cancellable jobs for grouping/layout and selected-window partial search, so changing selection does not repeat the all-pairs group calculation.

While recalculating, retain the old scene with an explicit pending state and suppress obsolete percentages/highlights. Results must match current library revision, workspace/database, selection and settings fingerprint before application. Errors leave observations and reviewed state intact; retry remains available.

Reuse and extend `completeLinkage.ts`; do not replace its tested every-pair invariant with anchor admission. Extend current matching diagnostics rather than discarding the provenance, unique-overlap and stale-context protections.

### Persistence and compatibility

Continue using the current IndexedDB stores and atomic expected-revision commits. Normalize absent new comparison fields when loading existing states, validating old backups and applying legacy migration. Export normalized current settings in new backups while preserving original recordings, decisions, relationships and archived undo history.

Raw earlier browser keys remain untouched. Removing old UI navigation does not delete old data, contracts, fixtures or migration helpers. Historical source that supports recovery/tests may remain in the repository without being a second primary atlas.

## Verification and acceptance

### Deterministic checks

- Test all seven nonempty parameter combinations, canonical ordering and rejection of an empty mask.
- Verify missing/modelled/incompatible selected channels never produce an eligible combined group score. Test distinct overlap counts, including disjoint measurements and repeated nearest-sample reuse.
- Verify complete-link every-pair threshold, no similarity chaining, symmetry, deterministic ID tie-breaking and permutation independence.
- Verify whole-window matches rank above partial matches, a better partial score cannot hide a qualifying whole result, and missing-channel percentages remain explicitly scoped.
- Verify all observation windows are candidates, self-comparison is excluded, all qualifying windows are highlighted, and the drawn-edge cap does not truncate totals.
- Verify emitter coordinates stay identical across parameter and display-filter changes. Test nonoverlapping islands/tiles, incomplete-evidence placement and repeated deterministic layout.
- Verify old state/backup migration, preserved review identities/evidence/undo, and invalid or stale writes leave prior state intact.
- Test camera anchoring, bounds fitting, viewport culling and interrupted transitions as mathematical invariants where practical.

### Browser acceptance

Use the synchronized synthetic workspace and an isolated pilot database:

1. Open v0.1.7 and verify one primary map with Similarity/Emitter arrangements and no separate Cycle explorer navigation or card pagination.
2. Inspect all seven selected-parameter combinations. Observe regrouping and tile animation in Similarity arrangement; verify stable emitter placement while masks change.
3. Select whole, scaled, changed-coordination, temporal-partial, missing-channel and unreviewed observations. Inspect candidate counts, full-first ranking, selected scopes and cross-group partial links.
4. Inspect solid/dashed/dash-dot connectors crossing tile backgrounds. Verify labels remain readable above selected/highlighted tiles throughout pan, zoom and layout transitions.
5. Exercise expanding eight connections, the legend, keyboard connections, dim/hide filters, Focus matches, selection focus, wheel/pinch anchoring and reduced motion.
6. Inspect overview, middle and close detail levels. Verify missing data remain visibly missing and selected parameter previews are consistent with active matching.
7. Import and review observations, accumulate support/variants/challenges and unresolved evidence, refresh, undo, export, replace and merge a complete backup. Verify IDs, originals and history survive map changes.
8. Check desktop and narrow viewport layout, keyboard selection, inspector dismissal and absence of runtime errors. Small-viewport emulation is not reported as physical-device validation.

### Capacity and practical limits

Retain the pilot envelope: at most 100,000 events per recording, 1 million retained source events, about 50 profiles and 500 windows. Renew the benchmark against **all 500 map windows**, not only the old 50 reviewed representatives. Record grouping time, selected-window matching time, cancellation, first visible scene, pan/zoom/view-switch latency, backup/restore and memory observations. Long operations need progress and must leave the map interactive; no silent window truncation is permitted.

The bounded matcher, 85% threshold, minimum overlap, projection and synthetic labels remain engineering choices. Synthetic correctness/performance checks do not establish measured-emitter accuracy or comprehensive analyst description quality.
