# Signal Atlas v0.1.7 Observation Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Replace the paginated directory and separate atlas navigation with one continuous observation map supporting similarity/emitter arrangements, parameter-controlled grouping and visible evidence connections as v0.1.7.

**Architecture:** Retain the current domain model, IndexedDB store and evidence workflow. Add shared comparison selection, worker-based all-window analysis, deterministic complete-link grouping/layout, and a layered SVG map with a separate camera/transition controller. Keep the existing HTML inspector and intake/backup tools around the map.

**Tech Stack:** React 19.2, TypeScript 5.9, Vite 7.3, Node.js 24+, native SVG and IndexedDB, Web Workers, Node's built-in test runner. Existing Python Playwright browser harness where available; Codex browser controls can execute the same browser assertions when that runtime is unavailable. No new application dependencies are planned.

**Spec:** [Approved observation-map design](../specs/2026-10-12-v0.1.7-observation-map-design.md).

**Baseline:** `ef3387b` on `codex/v0.1.7-map`, containing the approved design over preview commit `9fa26df`. Local Git author identity is unconfigured; use command-local `-c user.name=Codex -c user.email=codex@openai.com` for agent commits without changing global settings.

## Global Constraints

- Release identifier: **0.1.7**. Do not report implementation, measured accuracy or deployment before their checks/actions actually occur.
- One stable map tile per observation window; no collection pagination. Existing originals, attribution, reviewed IDs, scoped evidence and history remain intact.
- The seven nonempty combinations of Frequency, PRI and pulse width control grouping, suggestions, highlights and percentages together. Additional numeric channels remain inspectable and preserved.
- Use whole-window symmetric scores and every-pair complete-link grouping. Temporal partial matches create connections, never group admission.
- Each selected channel requires at least 16 distinct aligned supplied measurements initially; multiple selected channels additionally require 16 distinct simultaneously supported positions across the selected channels. Never silently omit a selected channel.
- Initial threshold: 85%; absolute/duration penalties: zero by default; overlap: 16. Preserve adjustable controls and provisional labels.
- Highlight all qualifying destinations; initially draw eight suggested connections, whole-window before temporal partial, with accurate totals and expansion.
- Put connection paths and screen-readable labels above tiles. Legend and text/icons supplement status colours.
- Display filters dim in place; Hide nonmatches does not repack; Focus matches changes camera only. Comparison-parameter changes regroup similarity arrangement, not emitter arrangement.
- Pointer-anchored wheel/pinch zoom, keyboard controls, approximately 950 ms interruptible arrangement movement, smooth camera focus and reduced-motion support.
- Pilot envelope: 100,000 events per recording, 1 million retained source events, about 50 profiles and 500 windows. Benchmark all windows, not just 50 reviewed representatives.
- Keep root and `/signal-atlas/` worker/asset paths working. Preserve lockfile/dependencies unless a demonstrated need justifies a change.
- Work only in isolated synthetic/pilot browser databases during verification. Do not trigger the feature branch's auto-deployment or create a release tag as a side effect of local implementation.

## Review Focus

- Missing or ambiguous selected channels, disjoint measurements and reused nearest samples must not become a combined match; owned by Tasks 1–3.
- Rapid parameter/selection/workspace changes must not apply stale percentages, groups or review targets; owned by Tasks 3 and 8.
- A target window supporting several patterns must require an explicit pattern choice and retain the actual compared interval; owned by Tasks 7–8.
- Zoomed/selected tiles and interrupted animations must not cover, detach or disable connection labels; owned by Tasks 5–6 and 9.
- Old backups/browse state and later imports must retain originals and review history during migration, restore and undo; owned by Tasks 1, 7 and 9.

New modules are intentionally focused:

| File | Responsibility |
| --- | --- |
| `src/agilityComparison.ts` | Selected-parameter canonicalization, channel resolution and eligibility |
| `src/agilityMapTypes.ts` | Shared analysis, geometry, camera and map presentation contracts |
| `src/agilityGrouping.ts` | Symmetric pair cache, complete-link groups and representative selection |
| `src/agilityMapLayout.ts` | Similarity/emitter island placement and collision-free observation slots |
| `src/agilityMap.worker.ts` | Group/layout and selected-window matching jobs |

| `src/agilityMapCamera.ts` | Pure camera, visible-bounds, interpolation and edge geometry |

| `src/agilityMapPresentation.ts` | Window status, filter masks and highlight/edge derivation |
| `tests/helpers/agilityMapFixtures.ts` | Deterministic views/library built from existing synchronized controls |

Shared types in `agilityMapTypes.ts`:

```ts
type ComparisonQuantity = 'frequency' | 'pri' | 'pulse-width';
type Point = { x: number; y: number };
type Bounds = { left: number; right: number; top: number; bottom: number };
type Camera = { x: number; y: number; zoom: number };
type Viewport = { width: number; height: number };
type AnalysisIdentity = { workspace: string; revision: number; settingsHash: string; inputFingerprint: string };
type WindowEligibility = { eligible: boolean; missing: ComparisonQuantity[]; jointMeasured: number; reasons: string[] };
type ObservationComparison = { kind: 'whole' | 'partial' | 'partial-channel'; score: number; eligible: boolean; weak: boolean; explanation: MatchExplanation };
type ObservationMatch = { targetWindowId: string; whole: ObservationComparison | null; partial: ObservationComparison | null; preferred: ObservationComparison | null; qualifying: boolean };
type SimilarityGroup = { id: string; members: string[]; representativeWindowId: string };
type GroupAnalysis = { groups: SimilarityGroup[]; membership: Record<string, string>; ineligible: Record<string, string[]>; pairIds: string[]; pairScores: Float64Array[] };
type MapIsland = { id: string; name: string; kind: 'similarity' | 'emitter' | 'insufficient'; members: string[]; bounds: Bounds; centre: Point };
type MapLayout = { positions: Record<string, Point>; islands: MapIsland[]; bounds: Bounds };
type WindowStatus = 'unreviewed' | 'reviewed' | 'unresolved';
type ReviewTargetChoice = { patternId: string; patternRevision: number; comparedWindowId: string };
type MapEdge = { id: string; fromWindowId: string; toWindowId: string; kind: 'reviewed' | 'whole' | 'partial'; label: string; relationshipId?: string; match?: ObservationMatch };
```

`MatchExplanation`, `WindowView`, `MatchSettings` and `LibraryState` remain defined/imported from their existing model/contracts. `MatchSettings` gains optional `parameters?: ComparisonQuantity[]` for compatibility; normalization returns settings with a required canonical mask. Null/incompatible comparison scores are represented as `NaN` in the public pair-score matrix, never as a fabricated projection distance; a private clustering matrix uses `-Infinity` for inadmissible pairs.

Execution follows Tasks 1–10 sequentially. Tests are written before product changes in each task. Use focused checks after each change and a full suite at integration/release gates.
